# Agent guide

## Project purpose

This repository contains Nick Boiko's single-page developer portfolio. It presents
Pdf&DocExplorer and Excel-utils with localized descriptions, screenshots, videos,
and links to their official distribution pages.

## Stack and architecture

- Next.js 16 App Router, React 19, and strict TypeScript.
- Node.js 22.18 or newer; Node.js 24 is recommended.
- npm with a committed `package-lock.json`.
- Static export configured in `next.config.ts`; production output is `out/`.
- No backend, authentication, database, or required runtime external services.
- Plain CSS and locally hosted fonts; preserve the existing responsive design.

Keep the static export working. Do not introduce server-only runtime features or
new dependencies without a concrete need for the requested change.

## Commands

Run commands from the repository root. In Windows PowerShell, use `npm.cmd` if
execution policy blocks `npm.ps1`.

```sh
npm ci
npm run dev
npm run check
npm test
npm run build
npm start
npm run test:e2e
```

- Development URL: `http://127.0.0.1:3000`.
- `npm start` requires an existing `out/` directory from `npm run build`.
- For browser verification, build first, run `npm start` in a separate terminal,
  then run `npm run test:e2e`.
- Browser checks use installed Microsoft Edge on Windows. Elsewhere, install
  Playwright Chromium if needed. `BROWSER_PATH` selects another executable.
- Browser screenshots are written to the ignored `artifacts/` directory.
- Rebuild before testing production changes; the static preview has no hot reload.

## Localization

Support all eleven application locales:

`en`, `uk`, `de`, `fr`, `es`, `it`, `pt-BR`, `ja`, `ko`, `zh-CN`, `ru`.

- Translate every new user-facing string, including accessibility labels.
- Preserve product names and original screenshot/video content.
- Translation arrays in `lib/i18n.ts` follow the insertion order of the English
  dictionary keys. When adding or reordering keys, update every translation array
  in the same position. Do not silently fall back to English for missing text.
- Preserve language precedence: URL `lang` parameter, saved preference, browser
  language, then English.
- Keep the HTML `lang`, title, description, URL, and saved preference synchronized
  with language selection.
- Allow for longer translated text and CJK characters at narrow viewport widths.
- Save source files as UTF-8. When reading them in Windows PowerShell, specify
  `-Encoding UTF8` to avoid misleading character corruption in terminal output.

The application language list was verified from its local documentation and
localization sources. The Store listing's language metadata is not the complete
application language list.

## Product content and media

Use verified product information. Do not invent features, pricing, testimonials,
download counts, or developer biography details.

- Pdf&DocExplorer: https://apps.microsoft.com/detail/9ns0crbdgtv6
- Excel-utils: https://github.com/nboyko75/Excel-utils
- Preserve asset provenance in `content/sources.json` when replacing Store assets.
- Preserve the Microsoft Office and WebView2 requirements in product copy.
- Keep media references centralized in `lib/media.ts`.
- DoxExplorer screenshots come from `artifacts/Screenshots`. Preserve the explicit
  locale mapping in `lib/screenshot-config.ts`, including Korean's English `us`
  fallback. Use all numbered images and dynamic counts in both gallery views.
- `npm run media:sync` runs before development and builds. Commit its public asset
  copies and manifest so builds also work without the ignored source folder.
- The bundled DoxExplorer trailer originates from
  `D:/Projects/Doc/DocExplorer/Video/Trailer4_2.mp4`. Runtime code must use the
  bundled public asset, not this machine-specific source path.
- The trailer is about 101 MB. Preserve deferred loading and stop playback when
  its dialog closes.
- Keep locally hosted fonts and their license together.

Reserved Excel-utils asset paths:

```text
public/media/excel-utils/presentation.png
public/media/excel-utils/trailer.mp4
public/media/excel-utils/trailer-poster.jpg
```

These files are intentionally optional. Do not create empty or fake media files.
The page detects their presence at build time: a real image replaces the
illustration, a real video enables its button, and its poster remains optional.
Rebuild after adding assets.

## UI and accessibility

- Preserve the single-page navigation and working Store, GitHub, and contact links.
- Maintain the existing light background, azure accents, and project presentation
  unless a design change is requested.
- Keep layouts usable on desktop, tablet, and mobile without horizontal overflow.
- Preserve visible keyboard focus, the skip link, semantic headings, image text
  alternatives, and reduced-motion support.
- Media dialogs must support Escape, focus containment, and focus restoration.
  Keep arrow-key navigation in the image viewer and native video controls.
- Avoid requesting absent optional assets or loading large videos on page load.

## Verification and scope

- For application changes, run `npm run check`, `npm test`, and `npm run build`.
- For UI, localization, or interaction changes, also run browser checks and inspect
  relevant desktop/mobile screenshots. Check longer translations for clipping.
- Existing browser checks cover all locales, persistence, gallery navigation,
  dialog keyboard/focus behavior, trailer metadata, and missing assets.
- Add targeted tests for new behavior when useful; documentation-only edits do not
  need a full build or browser run.
- Report any checks that could not run and the concrete reason.
- Edit source files, not generated `.next/`, `out/`, or dependency contents.
- Keep unrelated user edits intact. Update the README when commands, media
  conventions, or setup requirements change.
- Keep machine-specific temporary registries, credentials, and absolute local
  asset paths out of application code and the dependency lockfile.
- Treat publishing as separate work unless requested by the user.
